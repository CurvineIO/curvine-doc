# cv-docs-content

Authoring guide for the Curvine documentation site (Fumadocs on Next.js). This repository builds **curvineio.github.io** with Fumadocs; the legacy Docusaurus setup has been fully replaced.

Read [references/content-pipeline.md](references/content-pipeline.md) for the full architecture and framework reference before editing content.

## When to Use

- User asks to add a new documentation page
- User asks to write, update, or translate a blog post
- User asks to fix broken links or images in docs/blog content
- User asks to change how content is generated (`site/scripts/sync-*.mjs`, `site/source.config.ts`)

## Content Sources (always edit these)

| Content | English source | Chinese source |
| --- | --- | --- |
| Docs | `docs/<section>/<NN>-<name>.md` | `i18n/zh-cn/docusaurus-plugin-content-docs/current/<section>/<NN>-<name>.md` |
| Folder labels | `docs/<section>/_category_.json` | — |
| Blog | `blog/<YYYY-MM-DD>-<slug>/index.md` | `i18n/zh-cn/docusaurus-plugin-content-blog/<YYYY-MM-DD>-<slug>/index.md` |
| Static assets | `static/` → `/img/...` | — |

**Never edit `site/content/`, `site/public/`, `site/.source/`, or `site/out/`** — they are generated by `npm run sync` and gitignored.

## Workflow

### Step 1: Determine the change type

- New doc page → go to Step 2
- Blog post → go to Step 3
- Fix links/images → edit the source file, then verify with sync (Step 4)

### Step 2: Add a documentation page

1. Pick the section under `docs/` (e.g. `docs/1-Overview/`). Use numeric file prefix `<NN>-` for ordering; `sidebar_position` in frontmatter gives explicit ordering.
2. Write the English page:

```markdown
---
sidebar_position: 3
---

# Page Title

Content here. `:::note` / `:::tip` / `:::warning` admonitions are converted
to Fumadocs callouts by the sync script.
```

   Note: the page `title` is derived from the h1 — you do **not** need a `title:` frontmatter field unless you want to override it.
3. Mirror the translation at `i18n/zh-cn/docusaurus-plugin-content-docs/current/<section>/<NN>-<name>.md` (same relative path, translated body + h1).
4. New folder? Create `docs/<section>/_category_.json` with `label` (and `position`); the sync generates a folder `index.mdx` card list automatically.

### Step 3: Add a blog post

1. Create `blog/<YYYY-MM-DD>-<slug>/index.md`:

```markdown
---
title: "Post Title"
date: 2025-07-15
authors: [david]
tags: [teams]
image: ./cover.png
---

Post body. Images in the same folder are copied to `public/blog/<slug>/` and
referenced as `/blog/<slug>/cover.png`.
```

2. Author IDs must exist in `site/src/lib/blog.ts`; tag IDs should match existing tags.
3. Chinese version: `i18n/zh-cn/docusaurus-plugin-content-blog/<YYYY-MM-DD>-<slug>/index.md` — same frontmatter, translated body.

### Step 4: Regenerate and verify

```bash
cd site
npm run sync       # regenerate content/ + public/ from root sources
npm run typecheck  # must pass
npm run dev        # spot-check at localhost:3000
npm run build      # optional; CI does this on PRs
```

## Rules

- One page per PR; title the PR `docs: <what>` (or `blog: <what>`).
- Keep URLs stable: do not rename `docs/` sections or blog folders without a redirect plan — old Docusaurus URLs are preserved by the sync script.
- `<!-- truncate -->` markers are dropped by the sync script.
- Do not hand-edit generated directories (`site/content/`, `site/public/`, `site/.source/`, `site/out/`).
- Skill files: English only, follow the cv-* conventions from the Curvine main repo.
