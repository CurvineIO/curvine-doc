# Curvine Docs: Fumadocs Content Pipeline

Full reference for how the Curvine documentation site is built. The live site (curvineio.github.io) is **Fumadocs on Next.js**; the legacy Docusaurus setup has been replaced and removed.

## Framework and references

| Concern | Location |
| --- | --- |
| Fumadocs site (the real site) | `site/` — Next.js App Router, static export (`output: 'export'`) |
| Docs & blog **content sources** (edit here) | repo root: `docs/`, `blog/`, `i18n/zh-cn/...`, `static/` |
| Generated Fumadocs content (**do not edit**) | `site/content/`, `site/public/` (gitignored) |
| Content conversion scripts | `site/scripts/sync-content.mjs` (docs), `site/scripts/sync-blog.mjs` (blog) |
| Fumadocs config (collections, MDX plugins) | `site/source.config.ts` |
| Page components | `site/src/app/` (routes), `site/src/components/` (UI) |
| Locale / search / loaders | `site/src/lib/` (`source.ts`, `i18n.ts`, `blog.ts`) |
| Theme colors (Curvine green) | `site/src/app/global.css` (`--color-fd-primary`) |
| Deploy pipeline | `.github/workflows/deploy-fumadocs.yml` (builds `site/`, publishes `site/out` to GitHub Pages on merge to main) |

## Content flow

```
docs/1-Overview/01-instroduction.md   ─┐
i18n/zh-cn/.../current/...            ─┤  npm run sync (in site/)
blog/2025-07-15-what-is-curvine/index.md  ├→  site/content/*.mdx  →  Fumadocs pages
i18n/zh-cn/.../blog/...               ─┘
static/ (img/, install.sh, helm-charts/) →  site/public/
```

- **Always edit the sources** (`docs/`, `blog/`, `i18n/`, `static/`), then run `npm run sync` inside `site/` to regenerate `content/` and `public/`.
- `site/content/` and `site/public/` are **generated and gitignored** — never hand-edit them.
- The conversion preserves the old Docusaurus URLs (`/docs/Deploy/quick-start`, `/blog/2025/07/15/...`), sidebar order, and zh-cn locale routing (`/zh-cn/...`).

## What the conversion does (from site/README.md)

- **URLs are preserved.** Docusaurus drops the numeric ordering prefix (`1-`, `01-`) when generating slugs, so `/docs/Deploy/quick-start`, `/docs/User-Manuals/Operations/cli`, … keep working.
- **Sidebar order is preserved.** `sidebar_position` and the numeric file-name prefix are converted into `meta.json` `pages` arrays.
- **Category labels** come from `_category_.json` (`label`, `position`), with a Chinese `meta.cn.json` for translated titles.
- **The h1 is removed** from the body: Fumadocs renders the frontmatter `title` as the page heading.
- **Locale codes match the old site**: `en` (no prefix) and `zh-cn` (`/zh-cn/...`).
- **Links are rewritten** to the new URLs (relative links → absolute, stale absolute links resolved through the URL map, images copied to `public/doc-assets/...`).
- **Docusaurus-only syntax is normalised:** `:::note`/`:::tip`/`:::warning` admonitions → Fumadocs callouts; `## Title {#custom-id}` → `## Title [#custom-id]`; raw HTML comments → MDX comments; `<!-- truncate -->` markers dropped.
- **Folder landing pages.** Every folder gets an `index.mdx` (+ `.cn`) listing children as cards.
- **Blog posts** are flattened from `blog/<date>-<slug>/index.md` into `content/blog/<date>-<slug>.mdx`, images copied to `public/blog/<slug>/`. URLs keep their Docusaurus shape (explicit `slug:` frontmatter or date permalink `/blog/YYYY/MM/DD/<slug>`).
- **static/ is mirrored** into `public/` (images, helm charts, `install.sh`), so a clean checkout builds without hand-copied files.

## Docs page frontmatter

- `title` — optional; derived from the h1 if absent
- `description` — short summary shown in search and cards
- `sidebar_position` — explicit ordering
- `index: true` — folder landing pages only

## Blog page frontmatter

- `title`, `date`, `authors: [id]`, `tags: [tag]`, `image` (cover; falls back to first body image), optional `slug`
- Author IDs must exist in `site/src/lib/blog.ts`; tags are free-form but should match existing ones

## Development commands

```bash
cd site
npm install        # first time
npm run sync       # regenerate content/ + public/ from root sources
npm run typecheck  # tsc --noEmit (run sync first)
npm run dev        # http://localhost:3000
npm run build      # static export to site/out
npm run preview    # serve site/out
```

## Notes for agents

- `site/AGENTS.md` is auto-generated by `next dev` (gitignored) — the repo-root `AGENTS.md` is the canonical agent guide.
- Before editing any Next.js code, read `node_modules/next/dist/docs/` (the Next.js version here has breaking changes vs. training data).
- The sync pipeline is destructive for `site/content/`; always regenerate, never edit generated files.
- Deploys happen automatically on merge to main via `deploy-fumadocs.yml`. PRs only build + typecheck (no publish).
